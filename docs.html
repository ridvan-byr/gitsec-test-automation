GİRİŞ & MİMARİ VİZYON

Genel Bakış & Test Mimarisi Vizyonu

GitSec E2E Test Otomasyon Projesi, GitSec SaaS platformunun tüm kritik iş süreçlerini, kimlik doğrulama akışlarını, bulut depolama entegrasyonlarını (BYOS), yedekleme planlayıcılarını, restore sihirbazını, lisans yönetimini ve güvenlik kısıtlarını uçtan uca doğrulamak üzere geliştirilmiş enterprise-grade bir otomasyon mimarisidir.

Geleneksel ve kırılgan test yaklaşımlarının aksine; bu proje **Playwright v1.50+** ve **TypeScript** temelinde inşa edilmiş olup, **Page Object Model (POM)** tasarım deseni, **Dinamik Workspace Resolver**, **Otomatik Captcha & OTP Dinleyicileri** ve **Arka Plan Ağ Denetleyicileri (Audit Monitoring)** ile güçlendirilmiştir.

Neden Playwright & TypeScript?

  • Yerleşik Auto-Waiting (Otomatik Bekleme): Tıklama, doldurma veya navigasyon öncesinde DOM elemanının tıklanabilir ve görünür olmasını Playwright otomatik olarak bekler. Statik bekleme (`sleep`) ihtiyacını ortadan kaldırır.
  • İzole Tarayıcı Bağlamları (Browser Contexts): Testler arasında çerez ve oturum sızıntısı yaşanmaz; her test tamamen temiz bir bağlamda çalışır.
  • Tam Tip Güvenliği (TypeScript): Tüm Page Object selector'ları, API request/response tipleri ve konfigürasyon parametreleri derleme zamanında (compile-time) denetlenir.

KURULUM REHBERİ

Hızlı Başlangıç & Kurulum

Projeyi yerel geliştirme ortamınızda çalıştırmak ve test otomasyonunu yürütmek için aşağıdaki adımları takip edin: 

# 1. Proje bağımlılıklarını yükleyin
npm install

# 2. Playwright tarayıcı binary'lerini ve sistem kütüphanelerini kurun
npx playwright install --with-deps

# 3. Yerel Yönetim ve Koşum Sunucusunu (Express Server) başlatın
node tests-server.js
İpucu: Sunucu başladığında tarayıcınızdan http://127.0.0.1:3000 adresine giderek web arayüzü üzerinden testleri tek tıkla koşturabilir, canlı logları ve ekran görüntülerini izleyebilirsiniz.

DİNAMİK İZOLASYON

Dinamik Workspace Resolver (`workspace-resolver.ts`)

GitSec platformunda her kullanıcının kendine ait benzersiz çalışma alanları (Workspace ID) bulunur (Örn: 351, 352). Sabit bir çalışma alanı ID'sine bağımlı olmak testlerin farklı hesaplarda düşmesine neden olur.

Bu sorunu çözmek için geliştirilen getActiveWorkspaceId(page) fonksiyonu 2 aşamalı bir algoritma yürütür:

  • Aşama 1 (URL Parsing): Regex ile mevcut sayfa URL'sinden `/{workspaceId}/` numarasını tespit eder (`https://staging.dashboard.gitsec.io/351/dashboard`).
  • Aşama 2 (API Fallback): Sayfa henüz URL bazlı yüklenmediyse arka planda GitSec API'sine (`GET /api/workspaces`) istek atarak kullanıcının ilk aktif çalışma alanını döner.
// workspace-resolver.ts Akış Örneği
import { getActiveWorkspaceId } from '../../support/workspace-resolver';

test('Dinamik Yönlendirme Testi', async ({ page }) => {
  const wsId = await getActiveWorkspaceId(page);
  await page.goto(`https://staging.dashboard.gitsec.io/${wsId}/storage`);
});
OTURUM YÖNETİMİ

Oturum Paylaşımı & Global Setup (`auth.setup.ts`)

Her test dosyasında sıfırdan kullanıcı girişi yapmak zaman maliyetini artırır ve testi yavaşlatır. Projede **Playwright Session Storage Sharing** uygulanmıştır.

tests/e2e/auth.setup.ts dosyası testlerden önce bir kez çalışır, GitSec API'sine giriş isteği atarak oturum token ve çerezlerini diske (playwright/.auth/user.json) kaydeder. Tüm testler bu oturumu hazır olarak kullanır.

KİMLİK DOĞRULAMA

Kimlik Doğrulama & Captcha Yönetimi

Giriş, Kayıt ve Şifre Sıfırlama testleri yüksek hata toleransıyla yapılandırılmıştır:

  • reCAPTCHA & Turnstile Polling: Form doldurulurken veya buton tıklanırken Google reCAPTCHA iframe'i açılırsa Playwright force click ve polling mekanizmasıyla token'ı yakalar.
  • Mail.tm Geçici E-Posta: Kayıt testinde dinamik geçici e-posta açılır, aktivasyon maili polling ile dinlenip kullanıcı doğrulanır.
  • Gmail IMAP Şifre Sıfırlama: `gitsectest+2@gmail.com` hesabına gelen canlı `Reset Password` maili çekilerek token ayrıştırılır.
KOD SAĞLAYICILARI

GitHub & Bitbucket Entegrasyonları

Kod depolarının yetkilendirilmesi ve kapsama alınması adımları:

  • OAuth Popup Handling: Atlassian ve GitHub yetkilendirme pencereleri otomatik yakalanır, çerezler enjekte edilerek izinler onaylanır.
  • Include & Exclude Politikaları: Depoların yedekleme kapsamına dahil edilmesi veya çıkarılması test edilir. Lisans limiti aşıldığında 403 engeli doğrulanır.
BULUT DEPOLAMA

Bulut Depolama Entegrasyonu (BYOS)

AWS S3, Google Drive, OneDrive, Azure Blob ve Huawei OBS sağlayıcıları için form doldurma, bağlantı sınama ve silme testleri yürütülür.

Zod Validation Toleransı: Depolama sağlayıcısı silinirken ön yüzün `DELETE 200 OK` yanıtındaki `boolean` veriyi Zod hatasıyla yutması durumunda, test otomatik olarak sayfayı yenileyip (`reload`) silinmeyi doğrular.
ZAMANLAYICILAR

Planlayıcılar (Schedulers)

Günlük (Daily), Haftalık (Weekly), Aylık (Monthly) ve Cron formatında otomatik yedekleme kuralları oluşturulur ve silinir.

GERİ YÜKLEME

Geri Yükleme Sihirbazı (Restore Wizard)

Yedeklenmiş depoların hedef ortama geri yüklenmesi test edilir. Kapsam seçimleri (Code & Commits, PRs, Issues) doğrulanır.

LİSANS & ÖDEME

Lisans Değişimi & iyzico Ödeme Akışı

Free, Pro ve Enterprise paketleri arasındaki geçişler ve iyzico SMS OTP ödeme altyapı simülasyonu test edilir.

GÜVENLİK DENETİMİ

Audit Monitoring & Arka Plan Ağ Denetimi

`audit-helper.ts` fixture'ı, test çalışırken arka planda oluşan tüm konsol hatalarını, yutulan JS hatalarını ve 4xx/5xx API çökmelerini otomatik raporlar.

YÖNETİM PANELİ

Yerel Koşum Paneli Paneli (`tests-server.js`)

Node.js tabanlı Express sunucumuz (`http://127.0.0.1:3000`), testleri web arayüzünden görsel olarak başlatmanıza olanak tanır.

CI/CD HATTI

CI/CD GitHub Actions Entegrasyonu

Otomasyon paketinin her commit veya nightly build esnasında GitHub Actions üzerinde çalışması için `.github/workflows/playwright.yml` hazır durumdadır.

REHBER

Yeni Test Ekleme & Standartlar

Projeye yeni bir test yazarken aşağıdaki kurallara uyulması zorunludur:

  • Seçicilerde kesinlikle kırılgan XPath veya derin CSS kullanılmamalı; `getByRole`, `getByPlaceholder` veya `getByTestId` tercih edilmelidir.
  • Statik `waitForTimeout` (hardcoded sleep) kullanılmamalı, Playwright Auto-Waiting ve `safeGoto` tercih edilmelidir.
  • Tüm testler custom `test` fixture'ından türetilmelidir ki Audit denetleyicisi aktifleşebilsin.
